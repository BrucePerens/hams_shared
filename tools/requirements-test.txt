# Test-time Python tools the lint runner and the remote lint/test hosts need. NOT shipped in any product.
# Every line is a wheel pinned by SHA-256 (supply-chain rule, AGENTS.md); install with
#   python3 -m pip install --user --break-system-packages --require-hashes --only-binary :all: -r tools/requirements-test.txt
# pytest-xdist (+ execnet) was approved by Bruce on 2026-11-02 as a test-only dependency: run_linters.py uses
# it (pytest -n) when it can be imported and a step is not marked serial; without it the steps run as before.
#
# One file serves both runner architectures (Python 3.13): a package with a compiled wheel lists the hash of the
# manylinux x86_64 wheel (bruce-yoga) AND of the aarch64 wheel (mac1-vm); pip takes the one for its platform and
# refuses anything else. Pure-Python wheels have one hash.
#
# Versions are the dev box's (2026-11-03) for what the tests exercise, except where pip-audit (the check_pip_audit step audits this
# file) reports known vulnerabilities in the dev box's version: anyio, cairosvg, certifi, httpcore2, httpx2, opentelemetry-api, pillow
# (13.0.0; Debian's python3-pil stays 11.1.0 for everything outside the lint user) and pyjwt are newer. The tests exercised: hypothesis (tools tests), mcp (test_mcp_server),
# numpy (audio_card_characterize), cryptography (relay_ca / relay_signer tests), playwright (shack_console browser
# checks; the checks drive the system Chrome, no browser is downloaded), with their dependencies. Debian's own
# packages (apt, signed by the archive) supply the rest: python3-passlib, -pyinotify, -rjsmin, -bs4, -typeshed
# (the types-* stubs mypy needs; pyinotify has no wheel at all) and the python3-* that the odoo package depends on.
# curl_cffi, telnetlib3, cairosvg, zipstream-ng (with their dependencies) are what the hams_com daemon tests import beyond Debian's packages;
# av (PyAV) is deliberately NOT installed: the dev box does not have it, and mypy then type-checks every `import av` against PyAV's
# own annotations (check_untyped_utility_files failed on mac1-vm that way); hams_simulated_bots' tests need it and fail to collect on the
# dev box too.
# scipy 1.18.1 (manylinux_2_28 wheels, both architectures) is listed because numpy 2.5.0 below is newer than the <2.5 that Debian's
# python3-scipy 1.15.3 accepts: with numpy alone, every `import scipy.signal` on a host provisioned from this file warns "A NumPy version
# >=1.23.5 and <2.5.0 is required" (the dev box did, again, on 2026-11-07, after a sudo install of this file replaced /usr/local's scipy).
# It is the pairing recorded in hams_com devbox_tools/lima/README.md ("Python numpy and scipy"); check: python3 -W error -c 'import scipy.signal'.
# pyopenssl 26.4.0 is the dev box's too: Debian's 25.0.0 cannot import against cryptography 50.
#

#   --abi cp313 --abi abi3 --abi none --platform manylinux2014_<arch> --platform manylinux_2_28_<arch> ... -r PINS -d DIR`,
# then `sha256sum DIR/*.whl`, and compare every hash with the "digests" in https://pypi.org/pypi/<name>/<version>/json.
